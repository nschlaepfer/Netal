# Managed buffer-wrapper cleanup after a cut (V4)

This is opt-in source machinery. Existing constructors/selectors keep their native default; legacy callers remain untracked until explicitly integrated. No concrete neural provider, model, qualified backend, ANE placement, Metal runtime receipt, latency or gameplay result is supplied. Source compilation and CPU controls do not establish those results.

## Frame ownership and the one-use recording policy

Enable managed mode before the first frame. Mixing legacy Metal3/Metal4 selectors with that session is rejected. A managed session has six exact slot generations, one ordered queue and distinct Reserved → Encoding → CoreEncoded → Encoded → SubmitIssued states. Encoding and CoreEncoded transactions cannot be discarded while CPU encoding is in progress. Successful core encoding advances provisional scheduled history; finalization after output/export appends the marker and admits submission. Completion never changes scheduled parity/phase.

For buffer inputs, reserve with `newManagedFrameLeaseForCommandBuffer:allocator:queue:reset:error:` and call `encodeManagedFrameWithLease:...`. For texture inputs, `encodeManagedTemporalFrameToMTL4CommandBuffer:allocator:queue:...lease:error:` reserves the session/table slot before imports, then imports, encodes, exports and finalizes. A failed texture encode still returns its lease. Abandon the entire unsubmitted recording, then discard its lease; never append fallback after partial candidate writes.

Supply the actual allocator backing the CB. A lease pins it, but the caller must not reset the allocator until every associated lease reports `isRetired`. The public CB protocol exposes no recording-generation/reset authority. Object identity and an application counter cannot establish that an externally reused recording is new.

V2 therefore uses a **process-wide, one-use CB-object policy** for managed helpers. A weak, pointer-personality object registry rejects an already active CB across sessions, rejects foreign managed CBs smuggled as host work, and tombstones retired/discarded/tainted objects while they remain alive. Host CBs entering a helper are also claimed for one use, including a rejected submission after registry admission. No explicit reset/forget API bypasses this guard. Use a fresh CB object for the next recording. Weak object lifetime removes dead keys; a genuinely new object at a reused address is distinct from a live recording reset behind the API. This deliberately favors enforceable helper ownership over CB-object reuse; its cost is unmeasured.

Direct raw commits, re-recording a managed CB behind the helper, or early allocator resets remain violations of exclusive managed ownership. The registry does not intercept arbitrary Metal calls or make legacy callers tracked. Host synchronization must prevent external concurrent mutation of the supplied recording.

## Submission and feedback

End all CBs, then pass the actual ordered CB array and its ordered managed leases to the exact helper. Earlier dependencies must already have been submitted or appear earlier in the batch. The helper serializes actual commit API invocation order across sessions, not GPU completion. A session retains its bound queue. Rebinding requires a drained reset, with the prior queue's final release outside state locks.

Fresh options and the internally registered handler are prepared before issuing ownership. A known setup failure leaves work Encoded, unsubmitted and discardable. The handler captures a record whose immutable actual submission identity is published before invoking commit. It cannot certify a preparation-time callback. No reusable options or public success-injection method exists.

`SubmitIssued` is persisted immediately before actual commit invocation. A thrown/ambiguous invocation becomes `SubmitUnknown`; it is never retried or treated as unsubmitted. A valid inline callback may settle the record before the API returns, and return/exception handling cannot overwrite that settlement. Later exact nil-error, matching-marker feedback **may retire SubmitUnknown ownership**, while its content/epoch remains cut. Error feedback, wrong/missing markers and protocol failures remain quarantined, with no force-release/timeout shortcut.

Duplicate/stale callbacks are inert and cannot cut a new healthy generation or release reused slots. User observers and completion reaping run on the serial observer queue after internal retirement. They may reenter managed helpers without blocking an inline Metal callback against the submission mutex. Raw nil-error feedback is insufficient: inspect lease `status` / `isRetired`.

A terminal handle preserves only immutable sequence/frame identity and terminal cached status. Owner, CB, queue, allocator/resources, marker buffers and residency references are detached under state locks. Residency allocations and resource arrays are emptied, and their final releases occur outside those locks. Completion cleanup is asynchronous; known-safe ownership may be retired before its detached cleanup finishes. Retaining the terminal handle does not retain the session or frame payload.

## Marker, failures and reset

Each lease owns private fresh immutable full-token source backing and never-reused shared receipt backing, with explicit residency. The token includes random nonce, session, epoch, scheduled sequence and exact slot generation. The marker copy is encoded after final output/export, before encoding returns, never at submission. It waits on all prior queue stages with device visibility.

Only exact internal nil-error feedback plus complete token equality can retire ownership. Under exclusive helper submission this detects a reset/replaced recording whose marker did not execute. The marker is proposed source machinery, not hardware-validated proof or protection against an external caller directly executing/replacing private work behind the contract.

Public feedback documentation describes notification after workload completion but gives no sufficiently explicit failure-specific retirement guarantee for this implementation to release resources after an error. Such resources remain quarantined. Missing feedback and elapsed time do not prove drain. Independently established safe shutdown/lifetime boundaries remain outside this API.

A partial encoding failure changes temporal state only after an accepted transition on the authentic active lease. Stale, already submitted, terminal or wrong-state encode/failure calls cannot demote a successful frame or damage another epoch. Resource-attachment/Objective-C/foreign-exception paths cut the active unsubmitted transaction and retain it for explicit abandonment/discard.

Discard cuts the dependent chain. Other unsubmitted dependents must also be abandoned/discarded; submitted dependents remain pinned until their own exact verified feedback. External fallback/missed temporal input requires `invalidateManagedTemporalChain`; it releases nothing. Reset CPU fills are admitted only after every old owner is genuinely retired or explicitly discarded before submission. No successful steady-state frame waits for completion.

The managed adapter uses immutable neutral exposure when exposure is absent. It does not CPU-clear the shared live-exposure buffer. Its tables follow the authentic session slot, and the actual fence snapshot, textures, staging, descriptors and allocations are pinned before relevant commands. Metal3 semaphore claims remain conditional on a Metal3 CB; managed Metal4 does not consume those tokens. Static assertions bind six ledger slots to six session slots and eight phases to the phase contract.

## Queue ordering

Import, session input, export and marker use queue-scoped consumer barriers across prior passes/CBs on the same queue, with device visibility. Intra-pass native dependencies use encoder barriers. Commit order alone is not treated as sufficient memory visibility. Cross-queue continuation is rejected; queue replacement is a deliberate drained reset.

Public API evidence: [consumer barriers](https://developer.apple.com/documentation/metal/synchronizing-passes-with-consumer-barriers), [commit feedback](https://developer.apple.com/documentation/metal/mtl4commitfeedback), [feedback error](https://developer.apple.com/documentation/metal/mtl4commitfeedback/error), [command allocators](https://developer.apple.com/documentation/metal/mtl4commandallocator). API declarations/documentation establish intended contracts, not measured runtime behavior.

## Exact full-core views and two-phase provider preparation

The full-core seam replaces eleven PWin stages after Hiluma input and before Hiluma output. It does not consume raw scene color or substitute a single learned block. Native feature views are contiguous HWC FP16 with `{1,H,W,16}` input and `{1,H,W,40}` output. Width/height come from selected profile Hiluma templates, cross-checked against first/last stage extents. Phase is explicit for all eight required schedules. The views alias the reused arena at its canary offset; the maximum arena allocation is **not** the active input/output span.

`FeatureLayout.bytes` is an accessible end-bound from buffer base; `offset + spanBytes()` must fit it and actual backing length. Bounds, type, dimensions, strides, phase and overflow are validated. At 736×352 the active input is 8,290,304 bytes and output 20,725,760 bytes. A valid small input does not have to allocate or copy the entire maximum arena. Backend-owned residency uses active spans; the aliased external arena bound is not counted twice as two provider tensor sizes. `distinctInputOutput` describes distinct **provider-owned internal model** backing; external native views may alias.

The backend first prepares an immutable invocation with **no GPU emission**. It declares all resources, including internal packing/model tensors, heap, buffers, residency, pipelines, tables and fences. The session snapshots and pins the complete invocation/resources to the authentic outer lease before Hiluma's first GPU command. There is no second session lease or late resource out-array.

Provider preparation, resource getters, encoding and failed preparation's final object releases run outside the state lock. The authenticated Encoding admission gate rejects another frame's reservation/begin while this CPU transaction owns mutable session encoder state. Exact lease/epoch checkpoints after preparation and before/after provider encode reject a known cut before further recording. The one-shot context claim also revalidates the authentic ledger transaction, rather than trusting cached handle status alone. A cut racing after a validated claim may taint commands already being recorded; finalization/issue still reject that content and retain the unsubmitted recording for explicit abandonment/discard. These checks do not claim an atomic no-emission guarantee across unlocked arbitrary callouts.

At the seam, the prepared invocation receives a session-created context bound to that exact invocation, CB, native views, phase/reset and active outer lease. Only one exact `claimCommandBufferForInvocation:error:` succeeds. The context closes even on exceptions. The provider must fully pack all native HWC16 input into separate internal backing before any HWC40 consumer writeback, encode validated layout/ML/copyback dependencies on the same claimed CB, and use the appropriate queue/intra-pass barriers. It cannot own a private queue/commit, block on ordinary asynchronous prediction, or report session success/completion. Partial provider failure cuts the transaction; native fallback is not appended.

**Candidate registration remains unavailable.** This repository has no trusted full-core model/profile/layout/eight-phase numeric and temporal qualification authority. No provider is installed and no model/backing is distributed by this patch. Structurally valid descriptors remain unqualified; capability or encode success cannot enable the seam. Ordinary asynchronous CoreML needs a separate outer scheduler. Future Metal4 ML placement is automatic and is not a promise of Neural Engine execution: [machine-learning passes](https://developer.apple.com/documentation/metal/machine-learning-passes).

## Public buffer-wrapper failure cleanup

After an authentic Begin succeeds, every internal buffer-encoder NO now invokes the existing authenticated failure helper before returning. A cut between Begin and the internal guard therefore leaves the current recording FailedUnsubmitted and explicitly discardable, rather than stranded in Encoding. This does not auto-discard or release partial work: abandon the entire unsubmitted recording first. An older error workload stays quarantined and may still correctly block reset. Requests rejected before Begin, stale/foreign handles and submitted/unknown ownership retain their existing protections.

`python3 scripts/test-netal-sr-managed-buffer-wrapper.py` includes the actual public wrapper, actual authenticated helpers and actual authentication/nil/device guard prefix, which earlier fixtures omitted. It compares distinct-thread explicit cuts and older registered-error cuts against sealed V3, then checks V4 discard/reset recovery, preserved old quarantine, nil/device/Objective-C/foreign-exception paths and stale/foreign ownership. These are CPU/fake-endpoint controls; the native encoder and all model/GPU/device execution are excluded.
